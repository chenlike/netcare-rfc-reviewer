# RFC Review Studio

独立运行的方案审核工作台。用户在界面内填写自己的模型 API 地址、模型名和 API Key，维护规则组，上传 HTML 方案 ZIP 后开始审核。无需 HzTech、Redis、OBS 或外部数据库。

当前提供 **Node.js 本地服务 + Vue 界面**，浏览器直接打开使用。没有账号或管理员权限系统；模型配置和规则配置是两个独立页面。当前没有打包 Tauri/桌面安装器，运行需要 Node.js。

## 运行

安装 Node.js **22.19 或更高版本**（建议使用兼容的 Node 22 LTS）。项目使用 Node 自带的 SQLite。

```sh
npm ci
npm run build
npm start
```

打开 **http://127.0.0.1:4328**。首次运行不会自动插入演示规则、审核任务或任何 Key。

1. **模型配置**：填写 API 根地址、模型名称、API Key，保存。支持 OpenAI Chat Completions 兼容接口；DeepSeek 使用独立的思考参数适配。接口必须支持流式响应和工具调用。使用图片证据时，模型还需要支持图片输入。模型名称和能力以你自己的服务商配置为准。
2. **规则配置**：新建规则组，填写每项的标题、描述、等级和可选章节；也可导入 JSON。至少启用一条规则。
3. **方案审核**：上传 ZIP 并选择规则组。以文件名命名任务，自动选择书签主 HTML 或 index HTML；没有主页面命名时使用第一个 HTML。

保存模型配置后，新启动的审核使用新配置；进行中的审核保持其启动时的配置。API Key 留空保留原值，专门的清除按钮可以删除已保存的 Key。连接测试会向已保存的模型发送一条简短请求。

### 开发

```sh
npm run dev
```

前端 http://127.0.0.1:5188，后端 http://127.0.0.1:4328。前端支持热更新，修改后端代码后重新运行命令。开发代理固定连接 4328；修改开发后端端口时同步修改 `vite.config.ts`。

### 可选环境配置

不创建 `.env` 也可以运行。只有端口和数据目录使用环境变量；**模型地址和 Key 在界面内配置**。

```dotenv
PORT=4328
DATA_DIRECTORY=.data
```

路径相对启动目录解析。固定目录示例：Windows `D:/rfc-review-data`，Linux `/var/lib/rfc-review-studio`。服务仅监听本机回环地址，面向单机使用。

PM2 可选启动：

```sh
pm2 start ecosystem.config.cjs
pm2 save
```

使用单实例 fork 模式。不要为同一数据目录启动多个实例；进程锁会拒绝第二个进程。升级代码后执行 `npm ci && npm run build`，再 `pm2 restart rfc-review-studio`。

## 审核与展示

- 每份方案创建规则快照。改名、编辑、删除规则组不会改动已有任务。
- 同一方案的待审核 checklist 作为整体进入一个 pi-agent 会话，按需搜索和分段读取 HTML，共享已读内容和已查看图片。疑点未解决时不能提交通过结论。
- 只有实际读取过的原文或图片可以成为证据。程序验证唯一 CSS 选择器和引文，再保存单项结果。
- HTML 全宽预览，ZIP 只下载一次；样式、图片从浏览器内存读取。审核浮窗可拖动、收起；修改建议优先展示，审核依据可展开，支持安全 Markdown。
- 不执行方案脚本，不请求包外资源。不支持必须运行 JavaScript 才能产生正文的动态页面；需要包含静态正文的 HTML 导出包。
- 最多同时审核 8 份方案，单份内部顺序取证。默认每次执行 30 分钟、300 次模型请求、600 次工具调用；超过额度明确失败，保留已提交结果。
- 连续三轮没有工具动作会停止，避免无效空转。思考输出被截断时，允许扩容一次输出额度（最多 32768 Token，且不超过模型上下文）。
- “停止”保留结果；“继续审核”只处理未完成项。进程退出中断的任务下次打开会提示继续；删除任务会停止执行并删除本地记录和 ZIP。
- 当前活动只保存在进程内存，并输出截断日志，不保存模型内部思考。Token 数量以模型实际返回为准，输入未缓存和缓存读取分别计数。

ZIP 最大 50 MB，解压最大 150 MB、2000 个文件，正文最大约 500 万字符。无需逐资源访问云存储。

## 数据与备份

默认 `.data/`：

| 文件 | 用途 |
| --- | --- |
| `studio.sqlite`（及 WAL 文件） | 模型配置、规则组、任务和单项结论 |
| `master.key` | 本机 API Key 加密密钥 |
| `packages/<taskId>.zip` | 上传的方案原包 |
| `instance.lock` | 防止同一目录被多个进程同时运行 |

停止程序后备份**整个数据目录**，恢复时完整还原。API Key 使用 AES-256-GCM 加密，`master.key` 必须与数据库一起保管；拥有整个目录的本机用户仍可解密。页面不回传已保存的 Key。目录和 `.env` 已加入 Git 忽略规则。

## 示例和验证

```sh
npm run sample
npm test
npm run check
```

手动导入 `examples/checklist.json`，再上传生成的 `examples/sample-rfc.zip`。示例明确标注人工联调材料，维护窗口故意设为 30 分钟。真正审核这个示例会使用你配置的模型，正常计费。

自动测试全部使用本地模拟接口，不调用付费服务；包括真实 pi-agent HTTP 流式工具循环、共享提示词前缀、证据定位、图片按需阅读、限额防空转、密钥保存、任务恢复、取消删除和并发控制。

开发者需要可视化验证时，可在构建后运行 `node tests/ui-fixture.mjs`，打开 4329。该测试入口使用临时目录和假 Reviewer，**其模拟结论不能作为审核结果**；常规 `npm start` 不会载入它。

## 代码分层

```text
src/core/                 通用 pi-agent 执行器、预算、中止、简短遥测
src/agents/rfc-review/    RFC 文档解析、阅读工具、证据验证、审核提示词
src/server/              本地 HTTP、SQLite、任务调度与持久化
web/src/                 Vue 工作台、规则/模型设置、方案预览
tests/                   自动测试和显式 UI 测试入口
```

通用执行器不依赖业务存储。增加其他 Agent 可以实现 `AgentDefinition` 并使用 `AgentRegistry`；当前工作台和 HTTP 任务页面专门处理 RFC，不会自动为其他能力生成界面。
