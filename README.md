# Netcare RFC方案审核工具

桌面版可点击“从 Netcare 导入”，在软件原生弹窗中手动完成华为统一登录。Netcare 验证通过后，同一窗口继续连接方案下载服务，保留当前统一登录会话；仅在两个服务均验证成功并保存会话后才显示登录成功并关闭窗口。如果华为要求额外验证，会留在当前弹窗中完成。输入 `NE` 作业单号并选择规则组后，自动下载该单的数字化 HTML ZIP、打开方案并开始审核。会话过期时可重新登录，切换账号会清除旧会话。支持取消导入，下载上限 50 MB，失败重试不会重复创建同一次任务。当前支持 Netcare EBG 数字化方案的 IDP 导出，其他导出服务或离线附件可使用原有 ZIP 上传入口。

Netcare 与导出服务的 Cookie 按域分别使用，凭证加密保存在 `data/netcare-session.enc`，原生登录窗口缓存位于 `netcare-webview/`；凭证不会通过本机 HTTP API 返回，也不包含在工作空间备份中。账号密码和验证码仅在华为页面输入。升级时保留这两个目录即可复用会话。

新建审核分为“主方案”和“参考资料”两步。参考资料可选，支持 PDF、DOCX、HTML、TXT、Markdown、PNG、JPG、WebP；最多 12 份，单份 20 MB、合计 50 MB，PDF 最多 300 页。每次只能上传一个 ZIP 主方案，该方案可配多份参考资料。文本先在本机解析缓存，Agent 按需检索、分页精读或看 PDF 原页 / DOCX 内嵌图；扫描 PDF 需要具备图片理解能力的模型。HTML 参考资料仅提取正文，外部图片不会加载。结果仍定位到主方案，引用参考资料会注明文件名及页/段。

在“模型设置 → 基础审核 Prompt”编辑 Agent 的审核指令，可恢复默认。保存后对新任务生效，任务保留创建时的 Prompt 快照，继续审核不会受后续修改影响。配置导出包含此项，工作空间备份包含参考资料原件及任务 Prompt 快照。

独立运行的方案审核工作台。用户在界面内填写自己的模型 API 地址、模型名和 API Key，维护规则组，上传 HTML 方案 ZIP 后开始审核。无需 HzTech、Redis、OBS 或外部数据库。

提供 **Tauri Windows x64 / macOS ARM64 便携桌面程序**，ZIP 包内自带 Node.js 审核引擎和 Vue 界面。使用者无需安装 Node.js、打开终端或浏览器。没有账号或管理员权限系统；模型配置和规则配置是两个独立页面。

界面基于 **shadcn-vue / Reka UI / Tailwind CSS 4**，使用中性配色和紧凑侧栏。左下角可切换浅色、深色或跟随系统；选择写入本机数据库，桌面程序更换端口或重启后仍保留。侧栏可收起，审核浮窗可拖拽、向上折叠；修改建议优先展示，审核依据和规则按需展开。方案 HTML 保持原始样式，不反转图片颜色。

## 使用绿色版

每次发布同时提供四种附件：

| 平台 | 独立分发包 | 绿色版 |
| --- | --- | --- |
| Windows x64 | `windows-x64-setup.exe`，双击安装，包含全部运行环境 | `windows-x64.zip`，完整解压后双击 EXE |
| macOS ARM64 | `macos-arm64.dmg`，内含独立 `.app`，复制到可写文件夹后双击启动 | `macos-arm64.zip`，完整解压后双击 APP |

`.app` 是目录结构，GitHub Assets 无法直接存放目录，因此独立 APP 通过 DMG 分发。配置依然保存在程序旁边，请勿直接从只读 DMG 内运行。Windows 安装 EXE 与 ZIP 内的启动 EXE 不同，后者需与 `runtime/` 一起保留，不能单独拷走。

从 [GitHub Releases](https://github.com/chenlike/netcare-rfc-reviewer/releases) 下载对应 ZIP，**完整解压到用户可写的固定文件夹**：

- Windows x64：双击 `Netcare RFC方案审核工具.exe`。需要 Windows 10/11 与 Microsoft Edge WebView2 Runtime（多数系统已有）；缺少时从微软官网下载运行时。
- macOS ARM64：双击 `Netcare RFC方案审核工具.app`，支持 Apple Silicon / macOS 13+。请移动整个解压文件夹到固定位置后打开；不要在 ZIP 中直接运行。当前为 ad-hoc 签名，尚未 Apple 公证，首次打开可能需要通过系统设置 → 隐私与安全性允许打开。

不需要安装 Node.js，也没有安装向导。

桌面窗口自动管理内部引擎，使用系统分配的空闲本机端口，不与已有的 4328 服务冲突。内部服务要求本次桌面实例的会话，不能在其他浏览器中直接访问。重复启动会聚焦已有窗口。

关闭窗口时引擎停止，已保存结果保留；再次启动可继续未完成项。即使桌面进程异常退出，引擎也会因父进程连接断开而退出。

桌面配置和数据均放在**程序安装目录**，Windows 以 exe 所在位置解析，macOS 以 .app 所在文件夹解析，不受快捷方式工作目录影响：

```text
安装目录/
  Netcare RFC方案审核工具.exe  # macOS 为 .app，runtime 在 .app 内
  runtime/      内置运行环境
  data/         模型配置、Key、规则、任务、方案包和使用指引进度
  logs/         engine.log 等运行日志
  webview/      窗口缓存和本地会话
```

例如安装到 `D:/Netcare`，数据就在 `D:/Netcare/data`。请选择当前用户可写的安装位置；不可写时明确报错，不会回退到 C 盘用户目录。更新程序不覆盖这些数据；需要完整迁移时，先关闭程序再复制整个安装目录。

升级时，如果安装目录尚无工作空间，会自动从旧版 `%LOCALAPPDATA%/com.hezhitech.rfc-review-studio/data` 复制配置、数据库和方案包，校验成功后才启用。旧版必须已关闭；旧目录保留作备份，不再用于日常读写。已有安装目录数据时不会覆盖或合并。旧浏览器版 `.data` 不会自动搬迁，可通过界面备份迁移，或关闭两端后完整复制到新的 `data` 目录。

首次运行没有内置 Key 或任务；自动载入 24 项 RFC 预置规则。第一次进入自动展示使用指引，按“连接模型 → 设置审核规则 → 上传第一份方案”完成配置。指引根据已保存的配置更新进度；完成后不再自动弹出，随时可从侧栏“使用指引”重新打开。指引展示过一次后不再自动弹出；可随时从侧栏手动打开。

审核偏好不显示“同时审核方案数”；固定一次只审核一份方案，其余按队列依次执行，旧版或导入的并发配置也统一为 1。

## 从源码构建绿色版（开发者）

两种架构须使用对应的原生构建机。Windows x64 需要 Rust MSVC、Visual Studio C++ 构建工具和 Windows SDK；macOS ARM64 需要 Rust 与 Xcode Command Line Tools。两者均使用 Node.js 22.19.0。

```sh
npm ci
npm run check
# Windows
npm run desktop:build -- --bundles nsis
# macOS（在 Mac 执行）
npm run desktop:build -- --bundles app
# 验证最终运行时，生成 ZIP 与 SHA-256 校验文件
npm run desktop:portable
# 另生成 Windows 安装 EXE 或 macOS APP 的 DMG，保留绿色 ZIP
npm run desktop:distributions
```

产物位于 `release/Netcare-RFC-Reviewer-<版本>-windows-x64.zip` 或 `release/Netcare-RFC-Reviewer-<版本>-macos-arm64.zip`。生产依赖在各自架构上安装，包含 Node、SQLite、sharp、PDF 渲染组件；不包含用户数据和 API Key。

`npm run desktop:prepare` 生成内置运行环境；之后 `npm run desktop:dev` 可调试桌面壳。桌面模式不读取 `.env`，地址和 Key 在程序内配置。CI 同时发布独立分发包与绿色版。

### GitHub Actions 发布

`.github/workflows/release.yml` 使用两台 GitHub 托管构建机：`windows-2022`（x64）和 `macos-15`（ARM64），不需要自行注册 runner。

- 普通推送和 PR 不触发构建。手动 Run workflow 可验证构建，ZIP 存在 Actions artifacts（保留 14 天）。
- 推送 `v<版本>` 标签（如 `v0.0.1`）：以标签作为发布版本，在构建目录同步 package.json、锁文件、Tauri、Rust、界面及诊断版本，无需预先手动改版本。两套构建均通过后，将安装 EXE、包含 APP 的 DMG、两个绿色 ZIP 及各自的 SHA-256 发布到该标签的 GitHub Release。
- 修复工作流后补发已有标签：在 main 的 Actions → Portable desktop release → Run workflow 中填写 `release_tag`（例如 `v0.0.1`）。使用该标签的源码和 main 上的发布工具，不移动标签；已有 Release 会补齐产物。只点击旧运行的 Re-run 会继续使用旧工作流。
- 升级：退出程序，保留 `data/`、`logs/` 和 `webview/`，替换 exe + runtime（Windows）或 .app（macOS）。

```sh
git tag v1.2.0
git push origin v1.2.0
```

## 可选：浏览器服务模式（开发者）

安装 Node.js **22.19 或更高版本**（建议使用兼容的 Node 22 LTS）。项目使用 Node 自带的 SQLite。

```sh
npm ci
npm run build
npm start
```

打开 **http://127.0.0.1:4328**。首次运行不会自动插入演示规则、审核任务或任何 Key。

1. **模型配置**：填写 API 根地址、模型名称、API Key，保存。支持 OpenAI Chat Completions 兼容接口；DeepSeek 使用独立的思考参数适配。接口必须支持流式响应和工具调用。使用图片证据时，模型还需要支持图片输入。模型名称和能力以你自己的服务商配置为准。
2. **规则配置**：新建规则组，填写每项的标题、描述、等级和可选章节；也可导入 JSON。至少启用一条规则。
3. **方案审核**：上传 ZIP 并选择规则组。以文件名命名任务，自动选择书签主 HTML 或 index HTML；没有主页面命名时使用第一个 HTML。

保存模型配置后，新启动的审核使用新配置；进行中的审核保持其启动时的配置。API Key 留空保留原值，专门的清除按钮可以删除已保存的 Key。修改 API 地址时必须重新填写 Key，避免将原有凭据发送到另一端点。

连接测试使用**界面当前填写的配置**，无需先保存，会发送一条简短请求并显示耗时和可读错误。地址未改变时，空白 Key 可复用已保存的值。测试只验证文本接口连接，不代表已验证流式工具调用和图片能力。离开未保存的配置页面前会提示确认。

### 日常操作

- 启动时自动加入包含 24 项检查标准的“RFC 方案审核规则”，每个工作空间仅初始化一次，保留已有规则及后续修改、删除。也可通过“使用 RFC 预置规则”或导入 `presets/rfc-standard.json` 重新载入。预置数据有一处原文差异：网络观察规则标题要求 2 个运行高峰期，正文要求 1 个且大于 48 小时，使用前请统一标准。
- “数据与帮助 → 配置导入导出”支持迁移规则组、模型连接、审核参数与主题，可选明文携带 API Key；导入后 Key 在本机加密保存。规则新增为独立组，模型及偏好设置替换，不影响审核记录。
- 每次选择一个 ZIP 主方案，显示上传进度和错误；另可选择多份参考资料。上传失败可重试，同一上传请求不会重复创建任务。
- 列表支持搜索、状态筛选、每页 20 条、重命名；可批量继续未完成审核。成功上传的任务会立即进入队列，关闭上传窗口不会撤销它们。
- 详情页可导出 HTML、Markdown 或 JSON 报告。HTML 可离线阅读、打印；未完成项会单独标明，不会当作审核通过。
- “数据与帮助”展示本地数据位置、方案包大小、剩余磁盘空间，并提供备份恢复、诊断导出和常见问题说明。

```sh
npm run dev
```

前端 http://127.0.0.1:5188，后端 http://127.0.0.1:4328。前端支持热更新，修改后端代码后重新运行命令。开发代理固定连接 4328；修改开发后端端口时同步修改 `vite.config.ts`。

### 可选环境配置

不创建 `.env` 也可以运行。只有端口和数据目录使用环境变量；**模型地址和 Key 在界面内配置**。

```dotenv
PORT=4328
DATA_DIRECTORY=.data
```

路径相对启动目录解析。固定目录示例：Windows `D:/rfc-review-data`，Linux `/var/lib/rfc-review-studio`。服务仅监听本机回环地址，面向单机使用。

PM2 可选启动：

```sh
pm2 start ecosystem.config.cjs
pm2 save
```

使用单实例 fork 模式。不要为同一数据目录启动多个实例；进程锁会拒绝第二个进程。升级代码后执行 `npm ci && npm run build`，再 `pm2 restart rfc-review-studio`。

## 审核与展示

- 每份方案创建规则快照。改名、编辑、删除规则组不会改动已有任务。
- 同一方案的待审核 checklist 作为整体进入一个 pi-agent 会话，按需搜索和分段读取 HTML，共享已读内容和已查看图片。疑点未解决时不能提交通过结论。
- 只有实际读取过的原文或图片可以成为证据。程序验证唯一 CSS 选择器和引文，再保存单项结果。
- HTML 全宽预览，ZIP 只下载一次；样式、图片从浏览器内存读取。审核浮窗可拖动、收起；修改建议优先展示，审核依据可展开，支持安全 Markdown。
- 不执行方案脚本，不请求包外资源。不支持必须运行 JavaScript 才能产生正文的动态页面；需要包含静态正文的 HTML 导出包。
- 一次只审核 1 份方案，其他任务排队；单份内部顺序取证。默认每次执行 30 分钟、300 次模型请求、600 次工具调用；超过额度明确失败，保留已提交结果。
- 连续三轮没有工具动作会停止，避免无效空转。思考输出被截断时，允许扩容一次输出额度（最多 32768 Token，且不超过模型上下文）。
- “停止”保留结果；“继续审核”只处理未完成项。进程退出中断的任务下次打开会提示继续；删除任务会停止执行并删除本地记录和 ZIP。
- 当前活动只保存在进程内存，并输出截断日志，不保存模型内部思考。Token 数量以模型实际返回为准，输入未缓存和缓存读取分别计数。

ZIP 最大 50 MB，解压最大 150 MB、2000 个文件，正文最大约 500 万字符。无需逐资源访问云存储。

## 数据与备份

桌面版使用上述用户数据目录；浏览器服务模式默认 `.data/`：

| 文件 | 用途 |
| --- | --- |
| `studio.sqlite`（及 WAL 文件） | 模型配置、规则组、任务和单项结论 |
| `master.key` | 本机 API Key 加密密钥 |
| `packages/<taskId>.zip` | 上传的方案原包 |
| `instance.lock` | 防止同一目录被多个进程同时运行 |

“数据与帮助 → 导出备份”包含规则组、任务、已提交审核结论、用量统计和原始方案包，**不包含模型 API Key 或连接配置**。支持最多 500 个任务、500 个规则组，总内容最多 250 MB。备份包含方案内容，请按原方案的保密要求保管。

恢复只允许在没有任务和规则组的空工作空间中进行，现有模型配置会保留；导入前会完整校验 ZIP 和记录，恢复的未完成任务需要手动继续，不会自动调用模型。该备份也可用于从浏览器服务模式迁移到桌面版。

需要完整迁移凭据或超过页面备份容量时，停止程序后备份**整个数据目录**，恢复时完整还原。API Key 使用 AES-256-GCM 加密，`master.key` 必须与数据库一起保管；拥有整个目录的本机用户仍可解密。页面不回传已保存的 Key。目录和 `.env` 已加入 Git 忽略规则。

诊断导出包含版本、运行环境、任务数量和经过凭据脱敏的近期错误，不导出模型连接配置或方案正文。

## 示例和验证

```sh
npm run sample
npm test
npm run check
```

手动导入 `examples/checklist.json`，再上传生成的 `examples/sample-rfc.zip`。示例明确标注人工联调材料，维护窗口故意设为 30 分钟。真正审核这个示例会使用你配置的模型，正常计费。

自动测试全部使用本地模拟接口，不调用付费服务；包括真实 pi-agent HTTP 流式工具循环、共享提示词前缀、证据定位、图片按需阅读、限额防空转、密钥保存、任务恢复、取消删除和并发控制。

开发者需要可视化验证时，可在构建后运行 `node tests/ui-fixture.mjs`，打开 4329。该测试入口使用临时目录和假 Reviewer，**其模拟结论不能作为审核结果**；常规 `npm start` 不会载入它。

## 代码分层

```text
src/core/                 通用 pi-agent 执行器、预算、中止、简短遥测
src/agents/rfc-review/    RFC 文档解析、阅读工具、证据验证、审核提示词
src/server/              本地 HTTP、SQLite、任务调度与持久化
src-tauri/               原生窗口、引擎生命周期、单实例、跨平台便携打包
web/src/                 Vue 工作台、规则/模型设置、方案预览
tests/                   自动测试和显式 UI 测试入口
```

通用执行器不依赖业务存储。增加其他 Agent 可以实现 `AgentDefinition` 并使用 `AgentRegistry`；当前工作台和 HTTP 任务页面专门处理 RFC，不会自动为其他能力生成界面。
